Issue 1: TYPE COERCION VULNERABILITY (CRITICAL)
------------------------------------------------
v2 Problem:
  - hasOwnProperty(errorCode) lookup BEFORE type check
  - Objects with toString() returning known code bypass sanitization
  - Later string conversion displays malicious sentinel
  - Null prototype objects throw errors

v3 Fix:
  typeof errorCode === 'string' && Object.hasOwn(knownErrors, errorCode)
  
  - Type check FIRST, never coerce non-string values
  - Object.hasOwn() instead of hasOwnProperty()
  - Rejects: objects, arrays, null, undefined, numbers, symbols

Issue 2: CONSOLE SANITIZATION REGRESSION (CRITICAL)
----------------------------------------------------
v2 Problem:
  - Four console.error(..., error) calls REINTRODUCED from baseline
  - Undid v1 sanitization fixes
  - Raw error objects leaked to console

v3 Fix:
  console.error('...', error instanceof Error ? error.message : 'Unknown error')
  
  Fixed paths:
    - Session initialization error (line 245)
    - QR generation failed (line 282)
    - Verification error (line 383)
    - Proof submission error (line 417)

Issue 3: INCOMPLETE ERROR CODE COVERAGE
----------------------------------------
v2 Problem:
  - Missing 3 client-side error codes in installed SDK enum
  - timeout, cancelled, invalid_rp_id_format not handled

v3 Fix:
  Added all 3 client-side codes:
    - timeout: "Verification timed out."
    - cancelled: "Verification was cancelled."
    - invalid_rp_id_format: "Invalid service provider configuration."
